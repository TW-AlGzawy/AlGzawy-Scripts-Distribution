# AlGzawy License & Device V2 — تعليمات الإعداد

الحالة: الملفات منشورة في GitHub، ويجب تنفيذ D1 migration ثم إعادة نشر Production وفحص الأجهزة قبل بيع الاشتراكات.

## 1. قاعدة البيانات

افتح Cloudflare D1 → algzawy-control-db → Console.
افتح الملف portal/schema-license-v2.sql وشغّل أوامر CREATE TABLE وCREATE INDEX كل أمر بشكل منفصل، دون تعليقات البداية.
هذا يضيف portal_entitlements وportal_subscriptions وportal_device_keys وportal_access_events، دون حذف أو تغيير global_control.

## 2. تشخيص portal_not_configured

افتح https://algzawy-cloud-control.pages.dev/api/status
إذا ظهر portal_not_configured اقرأ حقل missing في JSON الجديد. يظهر أسماء إعدادات ناقصة فقط، لا قيمها.
تحقق أن مشروع Pages (Production) مرتبط بقاعدة D1 باسم DB، وأن Secret PORTAL_HASH_PEPPER طوله على الأقل 32 حرفًا. تحقّق أيضًا من PORTAL_ADMIN_TOKEN لإدارة المستخدمين. بعد الحفظ، أعد Deploy للإنتاج.
لا ترسل مفاتيحك السرية أو IP المشتركين لهذه المحادثة.

## 3. إنشاء اشتراك وتحديد السكربتات

عند فتح موقع المشتركين تظهر شاشة تسجيل الدخول وحدها، بينما إدارة المالك على المسار /admin/. لا يوجد إنشاء حساب ذاتي. رابط Telegram للتواصل مع المالك.
ادخل إلى https://algzawy-cloud-control.pages.dev/admin/ وسجّل الدخول برمز PORTAL_ADMIN_TOKEN، ثم أنشئ حسابًا. بوابة المشتركين الرئيسية لا تعرض رابط الإدارة. رمز المالك لا يُخزن في متصفح المشتركين؛ جلسة الإدارة تستخدم Cookie من نوع HttpOnly وSecure وSameSite=Strict لمدة 30 دقيقة مع حماية CSRF.
افتح الصلاحيات والأجهزة لهذا المشترك، وحدد سكربتاته المسموح بها واحفظ. يبدأ الحساب بـصفر سكربتات مرخصة.
حدد أيضًا صلاحية الاشتراك وتاريخ الانتهاء، أو عطله متى أردت.
العميل لا يرى سوى سكربتاته المرخصة، ولا يستطيع تفعيل سكربت آخر باستدعاء API.

## 4. ربط جهاز واحد بموافقة المالك

الزبون ينشئ رمز ربط مؤقت من الموقع. يثبّت AlGzawy Cloud Bridge v2 بالإضافة إلى السكربتات المرخصة.
على متصفح اللعبة ينشئ Bridge مفتاح ECDSA P-256 خاصًا غير قابل للتصدير ويحفظه في IndexedDB، ثم يرسل المفتاح العام فقط.
يظهر الجهاز في لوحة المالك بحالة بانتظار الموافقة. لا يعمل أي سكربت حتى تعتمد هذا الجهاز.
عندما تعتمد جهازًا جديدًا، يُلغى اعتماد الجهاز السابق لنفس الاشتراك.
تتحقق المزامنة من توقيع المفتاح، عمر الترخيص، قائمة السكربتات المسموحة، حالة الحساب والمفتاح المركزي Cloudflare.

## 5. IP والنسخ والحماية

نسجل IP الأول والأخير وسجل تغيّر IP ووقت الطلب. لا نربط الاشتراك بعنوان IP وحده لأنه يتغير مع شبكات الهاتف والإنترنت.
نقل ملفات Tampermonkey أو بيانات GM إلى جهاز آخر دون مفتاح IndexedDB لا يمنح ترخيصًا. لكن نسخ ملف تعريف المتصفح كاملًا أو تعديل سكربت JavaScript المكشوف قد يتيح تجاوز الحماية؛ لا توجد حماية مطلقة.
تحتاج سياسة خصوصية توضح جمع IP وبيانات الجهاز ومدّة احتفاظ محددة، مثل 90 يومًا.

## 6. فحوص قبل الاستخدام

(1) موقع دون تسجيل دخول يظهر صفحة الدخول وحدها.
(2) حساب جديد يرى صفر سكربتات حتى تمنحه الصلاحيات.
(3) يرفض API تشغيل سكربت غير مرخص.
(4) طلب ربط جهاز جديد لا يعمل حتى توافق عليه.
(5) تغيير الجهاز من المالك يمنع الجهاز الأول.
(6) إيقاف الاشتراك وإزالة صلاحية سكربت يوقف العمليات الجديدة عند المزامنة.
(7) عند Cloudflare OFF أو فقد اتصال الترخيص، لا تبدأ أوامر جديدة.
(8) التحقق البشري يؤدي إلى إيقاف احترازي ولا يتم تجاوزه.
(9) مزامنة مفتاح الجهاز الموقّعة ترفض التكرار والطلبات دون توقيع.
(10) اختبر على حساب لعبة تجريبي ولا تعتبر سلامة JavaScript دليلًا على نجاح اللعبة.

تحذير: ملفات تشغيل السكربتات الـ25 المعتمدة في توزيع V3 تشترط ترخيص Cloud Bridge v2. لا تحدثها للعملاء الحاليين قبل إتمام D1 وPages، وإلا ستتوقف فورًا حفاظًا على الترخيص.
